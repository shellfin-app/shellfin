# AGENTS.md — frontend (`src/`)

Applies on top of the root [AGENTS.md](../AGENTS.md). Deep reference: `docs/ARCHITECTURE.md` §8 (frontend), §9.5
(untrusted server content), §4 (IPC).

## Structure

- `features/<area>/` UI and actions per area; tests sit next to the code. `components/` shared primitives
  (`Dialog`, `Field`, `StatePanel`, ...). `state/slices/` Zustand slices (plain objects/arrays only: no `Map`/`Set`),
  read outside React with `useStore.getState()`. `lib/` pure helpers (identifiers and data only, no UI copy).
- `ipc/backend.ts` is the `Backend` interface; `tauriBackend.ts` wraps `invoke`/`Channel`; `ipc/mock/` is the
  in-memory MockBackend. `ipc/bindings/` is generated by ts-rs: never edit; `ipc/types.ts` only re-exports it.
- One action registry: `lib/actionIds.ts` (ids, menu layout, shortcut labels) + `features/actions/registry.ts`
  (behaviour). Menu bar, macOS native menu events, shortcuts, palette and context menus all use it. Add a new
  user command there, not as an ad-hoc handler.

## i18n workflow

1. Write `t("feature.key", { params })`; never a literal string. Technical data (hosts, paths, key types) goes in as
   interpolation params or `<code>`.
2. Add the English text to `i18n/locales/en/translation.json` (`npm run i18n:extract` adds new keys there, with the
   key as a placeholder value to replace, and only there; keep plural suffixes `_one`/`_other`). English is the only
   complete, CI-enforced locale. Other locales are optional: a key they leave out shows the English text, and
   `npm run i18n:missing` lists what each one lacks. If you translate a key (for example into Ukrainian,
   `i18n/locales/uk/translation.json`, plural suffixes `_one/_few/_many/_other`, terms in
   `../docs/i18n-glossary-uk.md`), `i18n/parity.test.ts` requires all plural forms of that language, the English
   `{{tokens}}` and a non-empty value; keys English no longer has fail it too (`npm run i18n:extract` prunes them,
   `scripts/i18n-missing.mjs --prune`). A key cannot be both a string and a parent.
3. Dynamic key families (`errors.<code>`, `action.<id>`, `menubar.<id>`, enum families) are listed in
   `preservePatterns` of `../i18next.config.ts`; extend it when you add a family.
4. `npm run i18n:check` (also fails when two menu bar titles of one locale share an Alt+letter mnemonic or one
   cannot be opened with Alt+letter; `&` marks a mnemonic other than the first letter, CJK titles need `(&F)`-style
   ASCII markers with the English letter; `scripts/menu-mnemonics-check.mjs`, CONTRIBUTING "Menu bar mnemonics") and
   `npm run lint` must pass. Show a `menubar.*` title anywhere but the menu bar through `plainMenuTitle` /
   `nativeMenuTitle` (`lib/menuMnemonic.ts`). In dev builds the pseudo-locale `en-XA` (`?xa=1`, `?xa=40`) shows
   missed strings and long text.
   Enter / Escape handlers on text fields ignore IME keys (`isImeKeyEvent`, `lib/ime.ts`).
5. Never concatenate translated fragments; format numbers/sizes/times with `i18n/format.ts`.
6. Server text goes through `displayServerText` (and `<ServerText>`); remote names/paths through
   `displayName`/`displayPath`; never into `<Trans>`, never as HTML.

## Mocks, scenarios and tests

- Vitest + jsdom + Testing Library. `src/test/harness.tsx` (`setupApp`, `setupConnected`) renders the whole app
  against a `MockBackend` scenario; `src/test/editorFixtures.ts` has connected-session helpers.
- Scenarios (`?scenario=<name>` in the dev server or `new MockBackend({ scenario })`): see `ipc/mock/scenarios.ts`
  (host-key cases, password/passphrase/2FA, drops and reconnects, save conflicts, binary/large files, uploads,
  terminal flood). The mock must model the real backend contract: when a Rust command or event changes, update the
  mock and its tests in the same change. Accepted secrets are the `MOCK_SECRETS` constants.
- jsdom has no layout or CSS cascade: mock `react-resizable-panels` with plain containers, stub layout where needed.
- `npm run test:freeze` loads the smoke build in jsdom with `Object.prototype` frozen (as Tauri does); new
  third-party code paths (xterm, CodeMirror, virtualizer) must keep it green. xterm's `toString` assignments are
  rewritten by `vite-plugins/freezeSafe.ts`; if an xterm upgrade changes the match count the build fails on purpose.
- Mock code is smoke/dev only: release builds must not contain it (`scripts/assert-no-mock.mjs`).

## Rules that bite

- Passwords and passphrases live only in dialog-local state until sent; never in Zustand, recents, logs or the URL.
  Never put local filesystem paths into IPC requests (native dialogs and drop tokens only).
- Shortcuts: match with `lib/keybindings.ts` (layout-independent, AltGr-safe); respect the terminal passthrough rules
  (ARCHITECTURE §8.7). Do not bind Tab in the editor.
- Pointer events for drag and drop (HTML5 DnD does not work on Windows). Do not open UI as a side effect of focus.
- Optimistic UI must not hide backend errors: use `reportError`/`guard` (`lib/reportError.ts`) for user-initiated
  promises; notices have levels (info/success/warning/error).
- Keep the CSP intact: no inline `<script>`/`<style>` in `index.html`, no new network origins, no `eval`.
